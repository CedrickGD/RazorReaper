# Languages

RazorReaper ships in English, German, Russian and Simplified Chinese. The picker is one
dropdown on **Settings**; switching is live and never asks for a restart.

Most of the app is translated. The pages that are not are listed at the bottom, and that is a
state the app is built to be in: a key with no translation falls back to English, and a page
that was never migrated is simply still English. Nothing breaks either way.

> **The German, Russian and Chinese are machine-translated.** They were produced by a model,
> not by native speakers, and read as a decent first draft rather than as something a person
> wrote. A sentence that is clumsy, wrong or funny in the wrong way is a bug worth reporting —
> through **Feedback & Support** in the app, or by editing the JSON file directly. Nothing but
> the JSON needs touching, and the app says as much under the picker itself
> (`language.description`).

## How it works

| Piece | Where |
| --- | --- |
| The lookup | `RazorReaper/Services/Localization/ILocalizer.cs`, `Localizer.cs` |
| The shipped languages | `AppLanguage.cs` — `AppLanguages.All` |
| The dictionaries | `RazorReaper/Resources/i18n/{en,de,ru,zh-Hans}.json` |
| The picker | `Components/Pages/Settings.razor` |
| The repaint | `Components/Layout/MainLayout.razor` |

`ILocalizer.T(key)` resolves against the active language, falls back to English, and falls back
again to the key itself. A missing key therefore shows as `settings.title` on screen — ugly,
and that is the point: it is visible in a screenshot.

`T(key, args)` fills `{0}`-style placeholders, formatted invariantly. A translation whose
placeholders do not match is returned unformatted rather than throwing.

**The dictionaries are embedded resources**, not files next to the exe (`RazorReaper.csproj`,
`Resources\i18n\*.json` → `RazorReaper.I18n.%(Filename)%(Extension)`). A translation that can
be deleted from disk is one that will be, and a missing one leaves a window with no way to
explain itself.

**There is no `CultureInfo.CurrentUICulture` and there are no satellite assemblies.** This is a
Blazor Hybrid: the UI renders on the renderer's dispatcher while services raise events from
timers and pool threads, so a thread-affine ambient culture would be right on some of those
threads and wrong on the rest. It also means number and date formatting are untouched — ARK
coordinates, INI values and hotkey labels are parsed and printed invariantly all over the app,
and a language switch that quietly turned `1.5` into `1,5` would break them.

### Which language a fresh install starts in

The stored choice (`rr.ui.language`) wins. With none, the machine's UI culture is matched
through its own parent chain: `de-AT` → German, `zh-CN` → Simplified Chinese. `zh-TW` resolves
to *English*, deliberately — traditional script is not shipped and English beats a script the
reader does not use. Anything else is English.

### The repaint

`MainLayout` publishes the language tag as a cascading value and re-renders when it changes. A
component that renders translated text declares the matching parameter and is repainted by the
framework; it needs no subscription of its own. `LanguageCascadeTests` explains the mechanism
and scans every component for the declaration.

The corollary is that a page must not cache a translated string — resolving it once in
`OnInitialized` and holding it in a field survives the repaint unchanged. Call `T` where the
string is rendered.

### The three surfaces the repaint cannot reach

- **The tray menu** is drawn by Win32 on the overlay's own thread. It is rebuilt on every
  right-click, so reading each label from the dictionary while it is being built is enough. Its
  one long-lived string, the icon tooltip, is re-sent when the language changes
  (`CrosshairService.OnLanguageChanged`). `TrayMenuTranslationTests` holds all of this.
- **The HUD overlay panel** is drawn with GDI+ from a snapshot on a timer, so it picks the new
  language up on its next frame. Nothing subscribes.
- **Lines already written to a list** — Home's activity timeline, the Sky Changer's output log
  — keep the language they were written in. Both lists are a session long, and re-deriving them
  on a repaint would mean storing a key and its arguments per row for no visible gain. An
  activity's *age* is resolved on read, because that would be stale anyway.

## Adding a key

1. Add it to **all four** JSON files. `TranslationParityTests` fails on a key that is in one and
   not the others, on an orphan in a translation, on a blank value, and on a placeholder that
   does not match English.
2. Use it as `@Localizer.T("your.key")` — inject `ILocalizer Localizer` and
   `@using RazorReaper.Services.Localization`.
3. Key shape is `area.thing` or `area.thing.detail`, flat, lowercase. The English file is the
   source of truth for what exists.

### What "translated" is allowed to mean

A page comes off the "Not yet" list below as soon as it contains one `Localizer.T(`, which is all
`UntranslatedPagesAreListedTests` can see. That was not enough. Six files reached the Done list
with their markup translated and their **toasts** still written out in English — Compact ARK,
Home's WiFi line, Steam Mods, Map Mods, and the accent and font cards — and the whole suite
stayed green, because a toast is not markup and nothing was reading it.

`TranslatedFilesWordNoToastInEnglishTests` reads it now. In any file that injects `ILocalizer`,
the first argument of `NotificationService.Show*`, `Notifications.*` and
`ActivityService.AddActivity` may not be an English literal. It ignores a literal that is only a
join (`$"{alreadyTranslated} {ex.Message}"`) and it ignores the severity argument. Its exemption
list is **empty** — it carried one entry, `CrosshairService`, which held a localizer for the tray
tooltip while its own save-failure toast stayed English, and that toast is a key since the
Crosshair page was migrated. The list stays for the next such service. **The count in the
table below is markup literals. A page's toasts, and any service that words messages for it, are
not in that number** — read the two tests together before calling a page finished.

`TranslatedSurfaceTests` enforces the other two halves: every key the app asks for exists, and
no key sits in the dictionaries with nothing rendering it. It reads the **whole argument list**
of a `T(…)` call, so `T(on ? "a.on" : "a.off")` counts as asking for both; it recognises a key
handed over to be resolved later (`TitleKey = "…"`, `DescriptionKey: "…"`); and for keys that
are computed rather than written — the sidebar's, the HUD's module and placement names, Launch
Options' per-flag prose, the Pixel page's category labels, the hotkey registry's, the Lifetime
guide's numbered steps — it reads them off the real catalogs in `GeneratedKeys()`.

## Migrating a page

1. **Find the literals.** Everything between `>` and `<` in the markup, plus `title`,
   `placeholder`, `aria-label` and `alt` attributes, plus every string handed to
   `NotificationService`/`Notifications` or `ActivityService.AddActivity` — including the ones in
   a `catch`, which are the last to be written and the first the user reads. If the page's
   messages are composed in a service, that service is part of the page: give it an `ILocalizer`.
2. **Replace them**, and add the page to `LanguageCascadeTests` by declaring
   `[CascadingParameter(Name = "Language")]` in its `@code` block. The scan will tell you if you
   forget.
3. **Add the English back to `TranslatedSurfaceTests.MigratedLiterals()`** so it cannot come
   back. Where an existing layout test asserted the wording against the razor file, point it at
   the key and pin the English in `TheEnglishWordingIsWhatItWas`.
4. Watch for three traps:
   - **A parameter default** (`public string Label { get; set; } = "Report an issue";`) is baked
     in at compile time. Make it nullable and resolve the fallback where it renders.
   - **A field initializer** cannot see an injected service, and a list built once never follows
     a switch. Make it a computed property.
   - **A `static` helper** cannot reach `Localizer`. Drop the `static`.
5. A page is worth migrating whole or not at all. Half a page in each language is worse than all
   of it in one — and "whole" means the toasts too, which is what the six files above got wrong.

## Translating

Rules the tests hold you to:

- **Product names stay in English**: Razor Reaper, RazorReaper, ARK, Premium, Freemium,
  Lifetime, Discord. A translated "Premium" makes the license view and the shop disagree.
- **Chinese is simplified.** A handful of traditional characters are checked for by name.
- **Placeholders survive.** `{0}` must appear in the translation if it appears in English.

Things deliberately left in English:

- **ARK's own nouns.** Map names, cave names, boss names, artifacts, tribute items, creature
  names, Alpha/Beta/Gamma, and the one-line notes attached to rows in the TP, drop, cave and
  boss datasets. These are what a player reads off the game's own screens; a translated
  "Ragnarok" is a row nobody can match up. The *frame* around them — the page a row belongs to,
  the count beside it, the column headings — is translated.
- **ARK's own switches and keys.** `-lowmemory`, `bUseOldThirdPersonCameraTrace`,
  `foliage.DensityScale 0`. They are typed into Steam or the console, not read by a person.
- **Feature names.** The automation scripts are called Yuty, Noglin, Tek Saddle, Armor Swap and
  Fed Suit in every language; the community uses those names and `DisplayName` is also what
  diagnostics and Rich Presence report. "Noglin" and "Transmitter" in the Lifetime guide are
  the same decision: a guessed item name is an instruction nobody can follow.
- **Stored identities.** A Map Mods spot's type (Cave / Landmark / Obelisk / POI) and the Pixel
  page's texture-category names are dictionary keys and folder names as well as labels. They
  keep their spelling; only the label on screen is looked up.
- **Log templates and telemetry.** They are read in a file by whoever is debugging.
- **Error codes.** `RR-E1003` is what someone quotes to support.
- **`NavPage.Label` and `NavGroup.Name`.** These are identities as well as words: the sidebar
  remembers the open group by its name, `NavPage.Category` is matched against it, and
  diagnostics and Rich Presence report the page label. The translated spelling lives under
  `NavPage.LabelKey` / `NavGroup.NameKey`, and the palette's subtitle under `DescriptionKey`.
- **Server and exception messages** that arrive already worded — the account service's errors,
  a failed update check's reported reason.
- **Plan names the shop sells under**, including `Lifetime`.

## What is translated, and what is not

Translated:

- **The chrome** — the sidebar, the command palette (page rows, deep links, every command row
  and its toasts), the notification bell and its tooltip, the announcement banner, the access
  gate, the elevation prompt, the premium and Lifetime gates, the colour field, the dropdown,
  the hotkey field and its read-only link, the hosted image and video placeholders.
- **The tray menu and the HUD overlay panel**, both outside the Blazor window.
- **Settings**, including the language picker, the accent card, the font card (both of which also
  word the line they write into the activity timeline) and the usage chip.
- **Home**, whole: status, storage, resources, hardware, the activity timeline, sound settings
  and the ARK paths — including the four reasons the network line has no name to show, which used
  to be written into the field as English sentences and stayed English through a switch.
- **Account, Feedback & Support, the support inbox, Credits, Troubleshoot, the not-found page.**
  Feedback's results are worded by `Services/Implementations/FeedbackService.cs`, which carries an
  `ILocalizer` of its own; what the server sends back and what an exception says are passed
  through as they arrive, as everywhere else.
- **The license overlay and the What's-new overlay**, and the update status line and its toasts.
- **Stretched Res**, whole, including both monitor pickers.
- **The Lifetime guide** (`/guides/dino-level`), including the guide text itself.
- **Game, Desync, Compact ARK, Launch Options, the three Vision tools, Global Hotkeys.**
  Compact ARK's two action buttons and all eleven of its toasts were finished in the second wave;
  before that the page was on this list with them still in English.
- **Sky Changer**, including its output log.
- **INI Changer**, whole, including the twelve built-in presets and all fifty-odd toasts — the
  page's markup was a third of its English. A preset's `Name` stays as it is: it addresses the
  image override, the last-applied preference and the zip entry, and it is what the community
  calls the preset, the same decision the automation scripts' names live under. Its line moved to
  `IniPreset.DescriptionKey`; a *custom* preset keeps `Description`, because that text is its
  author's, not ours.
- **Auto Clicker**, whole. Its three enums are worded rather than printed: the two header pills
  rendered `@mouseButton · @clickType` and `@positionMode` straight out of `ToString()`, which is
  English nobody ever wrote down as a literal and no grep would have found. Units keep their
  spelling — `h`, `m`, `s`, `ms`, `px`, `cps` — and so does the hotkey's own name.
- **Notifier**, whole, including everything `Services/Overlay/NotifierClientService.cs` words: the
  five alert types, the status line, the reason a connection failed, the alert text that goes to
  the HUD as well as to the list, and the six errors the watched-channel API throws — those reach
  the page as `ex.Message` and were the only English left on a page that otherwise looked done.
  The status line is held as a key and its arguments, not as a sentence: it stays on screen for
  as long as a connection lasts. A type's `Key` (`rare-dino`) stays as it is — it is the
  Preferences suffix, the backend's wire value and the CSS class. So do the three test-alert
  subjects and the mock tribe-log line, which imitate what ARK itself writes, and the default
  cluster labels, which are a text field the user owns.
- **Gamma**, whole. Three things on it stay English on purpose: a trigger's label, which is a
  key name (`F13`, `Mouse 4`); the six preset names, which are a text field the user owns —
  `GammaPresets.DisplayName` only seeds them at first run and they live in the config file from
  then on; and the Lua script itself, which is code for G HUB.
- **INI Builder**, whole, including the four built-in presets and everything
  `Services/Ini/GameIniService.cs` words. A preset's `Name` stays English because it is the
  identity the page writes to Preferences and compares back to draw the "last applied" badge;
  the spelling on screen is `NameKey`, the way `NavPage.Label` and `NavPage.LabelKey` split. A
  failed result now carries both: `Error` for the reader and `Reason`, the key, for the log and
  for telemetry — a telemetry note in whatever language the machine was in is one nobody can
  group.
- **Char Manager**, whole, including everything `Services/CharPresetService.cs` words. The slider
  names moved out of the parser: ARK's file names none of them, so those are RazorReaper's own
  words for byte offsets, and naming them where they render is what lets a switch reach them
  without the file being read again. The `" Copy"` a duplicate is named with, the `"Imported
  Preset"` fallback name and the parser's own `InvalidDataException` texts stay English — the
  first two are file names and the third is a diagnostic that arrives already worded.
- **File Modifier**, whole, including every outcome `Services/FileModifier/FileModifierService.cs`
  words: the page shows a `FileModResult`'s `Message` verbatim, so the service carries an
  `ILocalizer`. Its SeekFree scan reports a `SeekFreeKind` rather than a finished label, which is
  what lets the page name those rows — and re-name them on a switch without a rescan. A map row
  keeps its folder name, which is ARK's own.
- **Loading Screen**, whole, including the messages `Services/LoadingScreenService.cs` words for it:
  the page renders that service's `Message` verbatim, so the service carries an `ILocalizer` of its
  own and resolves each result where it is produced. ARK's own movie names stay English — they are
  the grouping key and the `@key` as well as the label. The converter under it,
  `Services/Media/VideoConverter.cs`, has one too: *Replace in ARK* hands the file to it and the
  failed `VideoConvertResult.Message` was spliced into the page's own result, which put an English
  sentence — "The source video no longer exists." — inside a German window. It words its six
  outcomes itself now and the page names the file the run stopped on around them. ffmpeg's own
  name stays as it is; it is a binary, not a word.
- **Paintings, Pixel Textures, Mutagen Prices, OC BPs, TP Locations, Underwater Drops, Bosses,
  Map Mods, Steam Mods.** Map Mods' add and delete toasts and Steam Mods' "Not detected" path were
  also second-wave work: only the "updated" half of each Map Mods pair had been migrated, so
  saving a spot spoke the reader's language and adding one did not.
- **Fonts**, whole: the three font cards, both installer walkthroughs, and every toast and
  activity line the installers write. The Steam launch options themselves (`-culture=Global`,
  `-culture=zh-Hans-CN`) are typed into Steam and stay as they are.
- **Line List**, whole: the toolbar, the editor, the table, the WTS/WTB modal and all fourteen
  messages. The **generated post is not translated** — it is pasted into ARK global chat and
  Discord for other traders to read, so `WTS:`, `WTB:`, `Muts`, `Gen`, `Base`, `offer` and the
  `HP / St / Ox / Fo / We / Me` shorthand stay English there. The same six abbreviations label
  the table's stat chips, so that column matches the post it produces; the editor spells the
  stats out and those labels *are* translated.
- **Server**, whole, including Bulk Add Favorites and the troubleshooting cards.
  `Services/Steam/SteamFavoritesService.cs` carries an `ILocalizer` of its own for the per-line
  rejection reasons it hands the page. The bulk status line keeps the last run's three counts
  rather than the sentence it built out of them, so a switch re-words it; a result row's detail
  is resolved when the row is written, the way any written line is. The endpoints, ports and the
  `steam://` URLs are addresses, and the saved list's `"Unknown"` is a stored sentinel — the word
  on screen is looked up from it.
- **Convert**, whose messages are mostly not its own. `Services/Media/MediaConverter.cs` carries
  an `ILocalizer` now — every `MediaConvertResult.Message` is a toast on this page and nowhere
  else. The destination list is a `static readonly` array that runs before any service exists,
  so it holds `LabelKey`s and the dropdown resolves them. Picking a movie under *Replace in ARK*
  hands the work to `Services/LoadingScreenService.cs`, which words that result and belongs to
  the Loading Screen page; this stream left it alone and the Loading Screen one migrated it, so
  both halves of that path speak the reader's language.
- **Scripts**, whole: the list, every per-script settings block, the calibration cards and the
  seventeen one-line descriptions. The scripts' own `DisplayName`s stay English — Yuty, Noglin,
  Tek Saddle, Fed Suit — as do the ARK binding names quoted in the hints (`'Move forward'`,
  `'Transfer item'`) and the Crafting modes *Watcher* and *Walk*, which the description names.
  A vision script publishes a `RegionTitleKey` rather than a title; the two keys it may publish
  are listed in `RegionTitles` and read off there by `TranslatedSurfaceTests`, because neither
  is ever a literal inside a `T(…)` call.
- **Crosshair**, whole: the editor, the pixel grid, the presets and profile lists, the library,
  every import path and the whole import guide. `CrosshairService`'s save-failure toast came with
  it, which empties the exemption list in `TranslatedFilesWordNoToastInEnglishTests`. The import
  summary used to be built by `CrosshairCodeParsers.Describe` out of English words; that method
  is gone and the page words the line, because the parser is a pure decoder with no localizer and
  the page was its only caller. Built-in preset names (Valorant, CS Classic, Sniper, …) and saved
  profile names stay as they are — they are stored identities, and a renamed preset is a row
  nobody can match up.
- **Building**, whole: eight sections of guide text, every figure caption, every `alt`, both
  checklists and the on-this-page nav. It is the one page with no C# of its own — the cascading
  parameter is its entire `@code` block. ARK's own structure names stay as they are inside the
  sentences (Tek Crop Plots, Tek Fence Pillars, Metal Fence Support, Metal Pillar), and so do the
  two layout names that are PvP jargon rather than words, *Mainfob* and *Cage TP*; *Tower* and
  *Underwater Tower* are ordinary English and are translated.

Not yet — nothing. The two streams that ran in parallel finished between them, and the table
that used to stand here is empty: every page under `Components/Pages` renders `Localizer.T`.
`UntranslatedPagesAreListedTests` reads an empty remainder as the finished state, not as a
missing section — what it still enforces is the other direction, that a component rendering no
translated text is either back on this list or in its own exempt list with a reason. A page
added tomorrow lands there until it is migrated.

No service is left wording an English message for a page, either. `CrosshairService` was the
last one: it held an `ILocalizer` for the tray menu while its own save-failure toast stayed
English,
and it was the single exemption in `TranslatedFilesWordNoToastInEnglishTests`, whose list is
empty now. Migrating a page still means giving its service an `ILocalizer` and resolving the
message where it is produced; the toasts are transient, so resolving on creation is enough.

`Services/Implementations/FeedbackService.cs` is the worked example. The third wave added
`FileModifierService`, `LoadingScreenService`, `CharPresetService`, `GameIniService` and
`NotifierClientService`; this one added `Services/Media/MediaConverter.cs` (Convert),
`Services/Steam/SteamFavoritesService.cs` (Server), `CrosshairService` (Crosshair) and
`Services/Automation/Scripts/CalibratableScriptBase.cs`, which publishes a key rather than a
message because a script has no localizer at all. The fix round after them added
`Services/Media/VideoConverter.cs` (Loading Screen).
`ServiceWordedMessagesFollowTheLanguageTests` drives the first of them through three languages
and back, because a literal scan cannot tell a message that is resolved from one that was
resolved once.
